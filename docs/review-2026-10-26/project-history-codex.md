# ReLSM project history, reconstructed from the Codex/ChatGPT task transcripts

**Date:** 2026-10-26. **Sources:** the 131 Codex task exports (local transcript bundle, `ReLSM-transcripts/codex_tasks/`, not in the repository) (PR #1, 2025-12-10, to PR #131, 2026-01-12), the five per-slice summaries (local bundle), and the defect list in `counter-review.md` (F01–F30, A1–A8, B1–B15, Tier C). Every number and quote below comes from those files. Nothing in the repo was read or modified for this document.

How to read the links: `#N` is the GitHub PR, `task` is the Codex chat (`https://chatgpt.com/remote/<task_id>`). Quotes marked *(owner)* are from the prompt the owner pasted; quotes marked *(Codex)* are from Codex's summary. Many owner prompts are review text produced by another LLM session and pasted in verbatim; the transcripts do not say which.

---

## 1. Timeline

### Phase 1: Dec 10–13, harness bootstrap (PR #1–#33, 33 tasks)

Goal: turn a pasted ablation-ladder `model.py` into a working training-and-eval harness. Codex imported the six variants and 50M–1B presets ([#1](https://github.com/jpturcotte/ReLSM/pull/1)), reworked ACT `steps_used` and added nano/1B-16k ([#2](https://github.com/jpturcotte/ReLSM/pull/2)), made `AlgorithmicDataset.__iter__` draw entropy seeds ([#5](https://github.com/jpturcotte/ReLSM/pull/5)), streamed `LanguageDataset` ([#6](https://github.com/jpturcotte/ReLSM/pull/6), [#7](https://github.com/jpturcotte/ReLSM/pull/7)), added `--seed` ([#9](https://github.com/jpturcotte/ReLSM/pull/9)), a Mamba-2 SSM plus JIT scan and `torch.compile` ([#10](https://github.com/jpturcotte/ReLSM/pull/10)–[#12](https://github.com/jpturcotte/ReLSM/pull/12)), AdamW no-decay groups ([#13](https://github.com/jpturcotte/ReLSM/pull/13)), a probabilistic `CurriculumSampler` with iterator refresh ([#14](https://github.com/jpturcotte/ReLSM/pull/14), [#15](https://github.com/jpturcotte/ReLSM/pull/15), [#17](https://github.com/jpturcotte/ReLSM/pull/17)), difficulty-ramped generators ([#16](https://github.com/jpturcotte/ReLSM/pull/16)), the `eval/` package and `eval_hub.py` ([#18](https://github.com/jpturcotte/ReLSM/pull/18)–[#20](https://github.com/jpturcotte/ReLSM/pull/20)), then eval correctness ([#22](https://github.com/jpturcotte/ReLSM/pull/22)–[#33](https://github.com/jpturcotte/ReLSM/pull/33)). Experiments referenced: needle lengths 512/2048/4096, "Phase 1 is 100M tokens"; no named runs. Bugs reported: fixed-seed replay, RAM bloat, worker duplication, padding contamination, `top_k=0` crash, lossy SSM averaging. torch was missing in the sandbox; 7 of 33 tasks ran anything, 5 of those compile-only.

### Phase 2: Dec 14–19, Windows hardening and grokking instrumentation (PR #34–#65, 32 tasks)

Goal: make `train.py` run on the owner's laptop and instrument it for grokking. Codex switched attention to SDPA with `mask=None` ([#36](https://github.com/jpturcotte/ReLSM/pull/36)), made `--compile` opt-in ([#39](https://github.com/jpturcotte/ReLSM/pull/39)), capped training-time eval at `--eval_max_new_tokens 32` ([#40](https://github.com/jpturcotte/ReLSM/pull/40), [#43](https://github.com/jpturcotte/ReLSM/pull/43)), added `FixedAlgorithmicDataset`, Grokfast and weight decay 1.0 ([#45](https://github.com/jpturcotte/ReLSM/pull/45)), BPE-only tokenization after a 0.0% accuracy run ([#47](https://github.com/jpturcotte/ReLSM/pull/47)), the llemma tokenizer ([#48](https://github.com/jpturcotte/ReLSM/pull/48)), token-based LR ([#51](https://github.com/jpturcotte/ReLSM/pull/51)), MAE and unified metrics ([#50](https://github.com/jpturcotte/ReLSM/pull/50), [#61](https://github.com/jpturcotte/ReLSM/pull/61)–[#64](https://github.com/jpturcotte/ReLSM/pull/64)), train accuracy and norms ([#52](https://github.com/jpturcotte/ReLSM/pull/52), [#53](https://github.com/jpturcotte/ReLSM/pull/53), [#56](https://github.com/jpturcotte/ReLSM/pull/56)), `metrics.json` at start then atomic writes ([#55](https://github.com/jpturcotte/ReLSM/pull/55), [#59](https://github.com/jpturcotte/ReLSM/pull/59)), checkpoint rotation with interrupt save ([#57](https://github.com/jpturcotte/ReLSM/pull/57)), and a pasted code review ([#58](https://github.com/jpturcotte/ReLSM/pull/58)–[#60](https://github.com/jpturcotte/ReLSM/pull/60)). Experiments: a suggested nano run `./runs/grokking_test` (3000 fixed examples, 50M tokens; prompt only) and a mod_add run whose LR bottomed out at ~50% budget. 3 of 32 tasks ran anything.

### Phase 3: Dec 20, eval repair and diagnostics burst (PR #66–#84, 19 tasks)

Goal: repair eval after a 25K-step run scored compare 76.6%, dyck 61.5%, parity 10.2%, successor 2.0%, everything else 0%, and MAE reached 10^30–10^60. Codex added safe numeric parsing, smooth difficulty, wsd/plateau LR and rebuilt IID/OOD grids ([#66](https://github.com/jpturcotte/ReLSM/pull/66), [#69](https://github.com/jpturcotte/ReLSM/pull/69)), hash-seeded eval sets ([#71](https://github.com/jpturcotte/ReLSM/pull/71)), per-module gradient diagnostics behind `--extended_logging` ([#73](https://github.com/jpturcotte/ReLSM/pull/73), [#76](https://github.com/jpturcotte/ReLSM/pull/76), [#77](https://github.com/jpturcotte/ReLSM/pull/77), [#84](https://github.com/jpturcotte/ReLSM/pull/84)), disabled the ssm_mem KV cache ([#75](https://github.com/jpturcotte/ReLSM/pull/75)), fixed MAE twice ([#78](https://github.com/jpturcotte/ReLSM/pull/78)), rebuilt `MetricsLogger` on a records list ([#79](https://github.com/jpturcotte/ReLSM/pull/79)), moved to HF-style labels after a suspected double shift ([#80](https://github.com/jpturcotte/ReLSM/pull/80)), split IID from OOD with OOD off by default ([#82](https://github.com/jpturcotte/ReLSM/pull/82)) and added stop-reason metrics ([#83](https://github.com/jpturcotte/ReLSM/pull/83)). Grokfast appears only as a `torch.compile` naming risk ([#75](https://github.com/jpturcotte/ReLSM/pull/75)). 0 of 19 tasks ran tests; both pytest attempts were skipped for lack of torch.

### Phase 4: Dec 21–25, competence curriculum and DAG (PR #85–#110, 26 tasks)

Goal: make the algorithmic phase competence-driven. Codex built the per-task EMA curriculum ([#85](https://github.com/jpturcotte/ReLSM/pull/85)), made auto train-eval procedural ([#87](https://github.com/jpturcotte/ReLSM/pull/87)), competence weights ([#88](https://github.com/jpturcotte/ReLSM/pull/88)), `metrics.json` on every log interval ([#90](https://github.com/jpturcotte/ReLSM/pull/90)), a Manager bypass at `num_workers=0` ([#93](https://github.com/jpturcotte/ReLSM/pull/93)), EOS appended before truncation ([#95](https://github.com/jpturcotte/ReLSM/pull/95)), a full resume payload ([#98](https://github.com/jpturcotte/ReLSM/pull/98)), EMA warm start and IID sync ([#100](https://github.com/jpturcotte/ReLSM/pull/100)), "Answer: " prompts with token-slice extraction and no `attention_mask` ([#103](https://github.com/jpturcotte/ReLSM/pull/103)), `torch.load` safe globals ([#104](https://github.com/jpturcotte/ReLSM/pull/104)), gates 70/50 ([#107](https://github.com/jpturcotte/ReLSM/pull/107)), the DAG curriculum ([#108](https://github.com/jpturcotte/ReLSM/pull/108)), a fix for starved locked tasks after the first DAG run ([#109](https://github.com/jpturcotte/ReLSM/pull/109)), and prompt masking plus a reversed unlock margin ([#110](https://github.com/jpturcotte/ReLSM/pull/110)). Run: `exp0_baseline_100M_5steps_wd1-e1_dag` (nano, alg_seq_len 32, accum 16, eval cap 32, workers 0; only root tasks had moved by step 8000). 2 of 26 tasks ran tests.

### Phase 5: Dec 26–Jan 12, hardening the DAG run (PR #111–#131, 21 tasks)

Goal: keep the DAG run alive. Codex persisted DAG state in checkpoints ([#111](https://github.com/jpturcotte/ReLSM/pull/111)), moved to dynamic padding ([#112](https://github.com/jpturcotte/ReLSM/pull/112)), ramped successor to 32 digits ([#113](https://github.com/jpturcotte/ReLSM/pull/113)), rewrote chain and the DAG ([#114](https://github.com/jpturcotte/ReLSM/pull/114), [#115](https://github.com/jpturcotte/ReLSM/pull/115)), removed the trailing space after "Answer:" ([#116](https://github.com/jpturcotte/ReLSM/pull/116)), which silenced per-task train-eval until [#119](https://github.com/jpturcotte/ReLSM/pull/119), moved `metrics.json` to JSONL ([#117](https://github.com/jpturcotte/ReLSM/pull/117), [#118](https://github.com/jpturcotte/ReLSM/pull/118)), added length-bucketed batching after tokens/sec fell 2820→388 and a CUDA OOM ([#120](https://github.com/jpturcotte/ReLSM/pull/120)–[#122](https://github.com/jpturcotte/ReLSM/pull/122)), guarded double bumps ([#123](https://github.com/jpturcotte/ReLSM/pull/123)), fixed Windows workers, an unpicklable lambda and stale worker snapshots ([#124](https://github.com/jpturcotte/ReLSM/pull/124), [#125](https://github.com/jpturcotte/ReLSM/pull/125), [#130](https://github.com/jpturcotte/ReLSM/pull/130)), added padding masks to thought/memory attention ([#126](https://github.com/jpturcotte/ReLSM/pull/126), [#127](https://github.com/jpturcotte/ReLSM/pull/127)) and a logging schema ([#128](https://github.com/jpturcotte/ReLSM/pull/128), [#131](https://github.com/jpturcotte/ReLSM/pull/131)). Runs: `..._dag_v6` (alg_seq_len 48, accum 16, eval cap 48, workers 0) and `..._dag` on Jan 11 (accum 12, workers 4). 2 of 21 tasks ran tests.

## 3. Instructions from the owner that led to defects

Each bullet quotes the prompt line and names the resulting defect. "Owner" means the text pasted into Codex; most of it was generated by another LLM session.

- **Hash-based eval seeding → F12.** [#71](https://github.com/jpturcotte/ReLSM/pull/71): "Update build_dataset to use a hash of the seed, task, and index." with `example_seed = hash((seed, task, i)) & 0x7FFFFFFF`. Python's `hash()` of a tuple containing a string is salted per process, so every process gets a different eval set; the v1/v2 re-evals share 0 prompts.
- **Grokfast placement → F11 / A1.** [#45](https://github.com/jpturcotte/ReLSM/pull/45): "Apply Grokfast (after loss.backward(), before optimizer.step())" with the comments "# After: scaler.scale(loss).backward()" and "# Before: scaler.unscale_(optimizer)". That puts the EMA update on every micro-batch's scaled gradient, which is the exponential feedback loop (×1.545 per update at accumulation 4).
- **Weight-decay changes → B7.** [#13](https://github.com/jpturcotte/ReLSM/pull/13): after Codex noted "Embeddings do get weight decay, which many small-model recipes still do", the owner replied with `or "tok_emb" in name_lower / or "lm_head" in name_lower  # tied embeddings` in the no-decay branch. [#45](https://github.com/jpturcotte/ReLSM/pull/45): "Update weight decay default to 1.0" (`# Was 0.1`); the DAG runs then ran with `--weight_decay 0.1` ([#109](https://github.com/jpturcotte/ReLSM/pull/109)). Result: 39% of parameters exempt, weight norm 152.6 → 358.1.
- **Capping eval tokens → F04 / B13.** [#40](https://github.com/jpturcotte/ReLSM/pull/40): "Add --eval_max_new_tokens (type=int, default=32, help="Limit generated tokens per example to prevent infinite loops")" and [#43](https://github.com/jpturcotte/ReLSM/pull/43): "Ensure it accepts max_new_tokens=32 (or similar default)". Seven of 21 OOD conditions cannot be answered in 32 tokens, and the [#20](https://github.com/jpturcotte/ReLSM/pull/20) signature default `max_new_tokens: int = 64` is what the metadata still records.
- **"Do not run tests" / "not requested" → everything in §4.** [#2](https://github.com/jpturcotte/ReLSM/pull/2) and [#5](https://github.com/jpturcotte/ReLSM/pull/5) end with "Testing Not run (per instructions)"; from #35 on, 94 tasks close with "Not run (not requested)". No transcript asks Codex to run `train.py`.
- **Accepting replay → A3.** [#5](https://github.com/jpturcotte/ReLSM/pull/5): "Given that 100k examples ≈ 12M tokens, and Phase 1 is 100M tokens, the repetition period is long enough that this is likely acceptable." The default stayed at `seed: int = 42` in the [#45](https://github.com/jpturcotte/ReLSM/pull/45) factory, so the stream restarted about 92 times in DAG-v12.
- **Per-epoch difficulty reset → A4.** [#17](https://github.com/jpturcotte/ReLSM/pull/17): "Reset tokens_seen = 0 in iter." and "Across Phase 1, you'll see a repeating easy → hard cycle every time the dataset is exhausted." Specified as intended behaviour; with workers it pins difficulty near 0 while the parent logs 1.0.
- **Sequence length and curriculum top end → F06 / A2.** [#109](https://github.com/jpturcotte/ReLSM/pull/109) ran `--alg_seq_len 32`; [#115](https://github.com/jpturcotte/ReLSM/pull/115) and [#130](https://github.com/jpturcotte/ReLSM/pull/130) `--alg_seq_len 48`, while [#113](https://github.com/jpturcotte/ReLSM/pull/113) pasted a config in which "successor ramps to 32 digits" and [#114](https://github.com/jpturcotte/ReLSM/pull/114) rebuilt chain "up to 32 digits, 8 steps". [#95](https://github.com/jpturcotte/ReLSM/pull/95) asked for EOS to be appended *before* `tokens[:self.max_seq_len]`, so truncated examples lose it.
- **Prompt-length masking by separate encoding → A6.** [#110](https://github.com/jpturcotte/ReLSM/pull/110): "encode example["input"] to determine the prompt_len" then `labels[:prompt_len] = -100`. [#116](https://github.com/jpturcotte/ReLSM/pull/116) diagnosed the space merge but asserted "The parsing logic in utils.py is already robust enough to handle this change", which broke train-eval the same day ([#119](https://github.com/jpturcotte/ReLSM/pull/119)); the `:=` merge for compare was never considered.
- **Deferring attention masks → padding-mask bugs (Dec 31).** [#103](https://github.com/jpturcotte/ReLSM/pull/103): "DO NOT introduce or plumb attention_mask into model attention at this time (leave masking exactly as-is today: only labels are masked)." Combined with [#36](https://github.com/jpturcotte/ReLSM/pull/36) ("If mask is None, call SDPA with is_causal=True"), thought and memory attention saw padding until [#126](https://github.com/jpturcotte/ReLSM/pull/126).
- **SSM scan spec → A7.** [#12](https://github.com/jpturcotte/ReLSM/pull/12): the pasted `ssm_scan_jit` recurrence `state = A_bar * state + dt_t * B_t_exp[:, t]` takes only B, C, dt and A; the projected value stream is never an input, and B/C/dt are `repeat_interleave`d across each group.
- **DAG gate numbers and margin → B5.** [#108](https://github.com/jpturcotte/ReLSM/pull/108): thresholds 0.95–0.99 with `--dag_patience_evals 4`; [#107](https://github.com/jpturcotte/ReLSM/pull/107): controller gates "from 85 and 55 to 70 and 50"; [#110](https://github.com/jpturcotte/ReLSM/pull/110) reversed the margin that [#108](https://github.com/jpturcotte/ReLSM/pull/108)'s follow-up had just fixed ("Or simply if score < minimum:"). The gates sit above the controller's dead band.
- **"Prefer the safe fix" → F07.** [#104](https://github.com/jpturcotte/ReLSM/pull/104): the owner offered `weights_only=False` or safe globals and said "Prefer the safe fix if possible." Codex registered the safe global, never ran it; a fresh process still raises UnpicklingError.
- **Atomic snapshot writes → F10.** [#59](https://github.com/jpturcotte/ReLSM/pull/59): "appending JSON lines creates invalid JSON files. Consider using JSONL explicitly or atomic writes." plus [#90](https://github.com/jpturcotte/ReLSM/pull/90): "metrics.json is not being updated every log interval anymore." Together: the whole snapshot is rewritten at every log, so I/O grows quadratically.
- **"You don't have to keep backward capability."** [#79](https://github.com/jpturcotte/ReLSM/pull/79): the legacy columns were dropped but `self.evaluations` was left as a duplicate of `self.records` (Codex: "it's effectively a duplicate list today").
